# Recipients & Beneficiaries API

Payees are managed in two layers:

- **Recipients** — your reusable payee records (name, account details, contact).
- **Beneficiaries** — links between your recipients and the payment provider's counterparty records.

## Recipients

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/recipients` | List recipients |
| POST | `/recipients` | Create a recipient |
| GET | `/recipients/{recipient_id}` | Recipient detail |
| PATCH | `/recipients/{recipient_id}` | Update a recipient |
| DELETE | `/recipients/{recipient_id}` | Remove a recipient |

## Beneficiaries

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/beneficiaries` | List beneficiaries |
| POST | `/beneficiaries` | Create a beneficiary |
| GET | `/beneficiaries/{beneficiary_id}` | Beneficiary detail |
| POST | `/beneficiaries/{beneficiary_id}/relink-recipient` | Attach a new recipient to the provider record |
| POST | `/beneficiaries/{beneficiary_id}/unlink-recipient` | Detach the current recipient |

Use relink/unlink when a provider changes a reference for an existing beneficiary — instead of deleting and recreating records, you move the link.

## Example

```bash
# Create a payee
curl -X POST https://app.buburuza.io/api/v1/app/recipients \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"name":"Acme Supplier Ltd","account_number":"…","routing_number":"…","country":"CA"}'

# Pay them
curl -X POST https://app.buburuza.io/api/v1/app/withdrawals \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"wallet_id":"w_…","recipient_id":"r_…","amount_minor":"250000","fee_quote_id":"<from fee-preview>"}'
```
