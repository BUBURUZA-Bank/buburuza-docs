# Onboarding API

Organisation onboarding lives under `/api/v1/app/onboarding/*`. It is a **step machine**: each step unlocks the next, and progress is durable — you can resume at any time.

## Step model

| Step | What happens |
| --- | --- |
| `legal_name` | Legal representative's name, set through the auth profile |
| `company_name` | Company name via `PATCH /onboarding/profile` |
| `kyb` | Hosted KYB verification (provider: Sumsub) |
| `payment_account` | Server-side provisioning; poll the status |
| `payment_agreement` | Hosted PSP terms in an iframe (only when required) |
| `dashboard` | Onboarding complete |

## Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/onboarding/state` | Current step (`next_step`) for resume |
| PATCH | `/onboarding/profile` | Set `company_name` (partial update) |
| GET | `/onboarding/kyb/doc-list` | Pre-KYB document checklist for the jurisdiction |
| POST | `/onboarding/kyb/doc-list/email-me` | Email the checklist |
| POST | `/onboarding/kyb/start` | Start hosted KYB; requires `country` (`CA` or `US`) |
| GET | `/onboarding/kyb/status` | Poll verification status |
| POST | `/onboarding/payment-account/start` | Trigger account provisioning |
| GET | `/onboarding/payment-account/status` | Poll provisioning; read-only |
| GET | `/onboarding/payment-agreement/link` | Hosted terms URL (`agreement_url`, `display_mode: iframe`) when required |
| POST | `/onboarding/payment-agreement/complete` | Confirm the agreement callback |

## KYB flow in practice

```bash
# Where am I?
curl https://app.buburuza.io/api/v1/app/onboarding/state \
  -H "Authorization: Bearer <access_token>"

# What documents will be needed?
curl https://app.buburuza.io/api/v1/app/onboarding/kyb/doc-list \
  -H "Authorization: Bearer <access_token>"

# Start verification (Canada)
curl -X POST https://app.buburuza.io/api/v1/app/onboarding/kyb/start \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"country": "CA"}'
```

## Payment account provisioning

You do **not** create the payment account yourself. After KYB passes, provisioning starts server-side. The client's job:

1. Poll `GET /onboarding/payment-account/status`.
2. If `agreement_required` is `true`, fetch `GET /onboarding/payment-agreement/link` and embed `agreement_url` in an iframe (web) or WebView (mobile), then `POST /onboarding/payment-agreement/complete` after the callback.
3. Keep polling until the account is `ACTIVE`.

<Note>
Some payment providers do not require hosted terms. When `agreement_required` is `false` (or the link returns 404), skip the agreement step entirely.
</Note>

## Prerequisites

| Endpoint | Requires |
| --- | --- |
| `profile` | Completed signup credential (`SignupSession`) |
| `kyb/start` | `country` in body (`CA` \| `US`) |
| `payment-account/status` | KYB green (provisioning may already be running) |
| `payment-agreement/link` | `agreement_required: true` in the status response |
| `payment-agreement/complete` | A pending agreement; `Idempotency-Key` supported |
