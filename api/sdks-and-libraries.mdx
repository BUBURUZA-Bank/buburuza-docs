# SDKs & Libraries

Buburuza does not ship official SDK packages yet. The platform is API-first, and the contract is published as **OpenAPI 3.x** — the same specification the web and mobile clients are generated from.

## OpenAPI specification

The client API contract covers:

- **Auth** — signup, WebAuthn, sessions, MFA
- **Onboarding** — state, profile, KYB, payment account, provider agreement
- **Accounts & wallets** — accounts, wallets, balances, deposit instructions, documents
- **Money movement** — transfers, withdrawals, transactions, payment intents, recipients, beneficiaries, rates

Ask our team for the current bundle, or import it directly into:

- [Swagger Editor](https://editor.swagger.io) — interactive browsing
- Redocly — `npx @redocly/cli preview-docs openapi.yaml`
- Your IDE's OpenAPI plugin

## Client generation

Generate typed clients from the spec with standard tooling:

```bash
npx @openapitools/openapi-generator-cli generate \
  -i openapi.yaml \
  -g typescript-fetch \
  -o ./generated
```

Generators exist for TypeScript, Swift, Kotlin, Python, Go, and most mainstream languages. The envelope type (`data` + `correlation_id`) is defined per response in the spec, so generated clients are fully typed.

## Webhooks

Buburuza does not currently expose outbound webhooks to client applications. **Poll** the status endpoints instead:

- `GET /transfers/{transfer_id}` / `GET /withdrawals/{withdrawal_id}` — operation status
- `GET /transactions` — money events (inbound deposits appear here automatically)
- `GET /onboarding/kyb/status`, `GET /onboarding/payment-account/status` — onboarding progress

Use [Idempotency-Key](/api/overview) on mutations and poll with reasonable backoff (start at a few seconds, cap at minutes).
