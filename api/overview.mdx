The REST API is the same contract the dashboard uses. Anything you can do on a screen you can do over HTTP, against the space you are currently acting in.

## Base URL and versioning

The public prefix is `/api/v1`, owned by the gateway. Money-movement resources are mounted under `/app`:

```text
https://<host>/api/v1/app/accounts
https://<host>/api/v1/app/transfers
```

<Note>
  The OpenAPI document published with the platform is the authoritative reference for exact request and response shapes. This section explains the model; the specification governs the details.
</Note>

## Authentication

Every call carries a bearer token:

```bash
curl https://<host>/api/v1/app/accounts \
  -H "Authorization: Bearer <access-token>"
```

Access tokens are short-lived and refreshed while a session is live. See [Authentication](/api/authentication) for how a session is established and refreshed.

## The space is implicit

A request acts on the space you are currently in — the company space you switched to, or your personal one. You do not pass the space as a parameter; you switch it, and subsequent calls follow. This is why the same path returns different accounts for the same user.

## Response envelope

Every successful response is wrapped:

```json
{
  "data": { },
  "correlation_id": "01J8Z..."
}
```

`data` carries the resource. `correlation_id` identifies the request end to end — quote it when you contact support and the exact request can be found.

## Errors

Errors carry a machine-readable `code`, a human `message`, and a `data` object with the specifics:

```json
{
  "code": "quote_expired",
  "message": "The fee quote is no longer valid",
  "data": { },
  "correlation_id": "01J8Z..."
}
```

Branch on `code`, never on `message` — messages are for people and may be reworded. Some codes originate at the payment provider and are passed through unchanged rather than remapped, so treat the set as open and always have a default branch.

| Situation | What you get |
| --- | --- |
| Not signed in, or token expired | `401` |
| Verification has not passed, or the tier does not allow the operation | `403` |
| Resource not in this space | `404` |
| Request understood but rejected | `422` with a specific `code` |

## Amounts

Monetary values are **decimal strings**, not floats. Parse them with a decimal type. A payment carries three of them — the net amount, the fee, and the total debited — and net plus fee always equals the total.
