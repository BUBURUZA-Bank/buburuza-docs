## Keep your sign-in and unlock methods distinct

| Item | What you use it for | Where to manage it |
| --- | --- | --- |
| Passkey | Complete a device or password-manager challenge to sign in. | Settings → Passkeys. |
| Authenticator code | Enter the current code generated by the authenticator linked during setup. | Use the authenticator entry created from Buburuza’s QR code or setup key. |
| Recovery code | Regain access through the recovery flow. Each saved code works once. | Save the codes during setup; use Recover when needed. |
| App passcode | Unlock the mobile app. | The mobile setup and unlock screens. |
| Active session | A device/browser currently signed in. | Settings → Active sessions. |

Signing out a session does not remove its saved passkey. To remove a passkey, use the separate passkey action. The web option to sign out all other sessions leaves the current session active.

If you use a recovery code, the confirmation marks it used and offers to set up a passkey for the device. If you have no recovery codes, use the contact-support link on that screen. Never send any of these codes or setup keys in a support conversation.

## App passcode, card PIN and wallet recovery

The six-digit **app passcode** unlocks app actions such as viewing a card PIN. The four-digit **card PIN** belongs to a selected card. Creating a new card PIN does not replace the app passcode.

A **secret phrase** is the recovery key for a phrase-based wallet. A manual backup records those words in order. An **iCloud backup password** encrypts that wallet’s phrase in its iCloud backup. It is separate from the app passcode. Buburuza’s backup flow warns that this encryption password cannot be reset for you.

A **Swift wallet passkey** is a key to that wallet. Its safety screens warn that deleting it can lose access to the wallet and funds. This is different from using a passkey simply to sign in to a Buburuza account. Use the instructions for the exact credential or wallet type you are managing.

Never provide support with your passcode, card PIN, secret phrase, private key or backup-encryption password.

## Sign in to Buburuza on the web

_Applies to: Web_

Use the sign-in route for an existing account. The web sign-in flow offers passkey and recovery journeys alongside email confirmation.

1. Open the official Buburuza web app through your usual trusted entry point.
2. Enter the email associated with your existing account.
3. Complete the passkey, email-code, or other security challenge shown for your account.
4. If asked to use a recovery method, follow the dedicated recovery flow.
5. After Dashboard opens, check the selected account or company before continuing.

**Troubleshooting and important distinctions**

- If you see that an account already exists, use sign-in instead of sign-up.
- If a security method is unavailable, use the alternative shown on the screen. Opening another account will not recover access to your existing funds.

## Set up and use a passkey

_Applies to: Mobile and web_

A passkey is one of the security options available in Buburuza. Setup and sign-in use a prompt from your device or password manager.

1. During account setup, choose Set up passkey and follow your device prompt.
2. To add one later on mobile, open Settings, then Passkeys, and choose Create new passkey. On the web, open Settings, then Passkeys, and choose Add passkey.
3. Complete the device or password-manager prompt. Check the passkey list for the added entry; the web list includes added and last-used information.
4. When signing in, use the passkey saved for the account and complete the device challenge.

**Troubleshooting and important distinctions**

- If you cannot find your passkey, check that you are using the device or password manager where you saved it.
- Use another sign-in or recovery option offered by Buburuza if the passkey is unavailable. Contact support if you cannot complete recovery.

## Set up an authenticator for two-factor authentication

_Applies to: Mobile and web_

Two-factor authentication adds a code from your authenticator app to the account-security process. Complete the setup before leaving the confirmation screen.

1. At security setup, choose Set up 2FA instead on mobile or Set up a code instead on the web.
2. On mobile, copy the setup key into a new entry in your authenticator app, then choose I’ve added the key in Buburuza.
3. On the web, scan the displayed QR code with your authenticator app. Use the manual-key option if you cannot scan it.
4. Return to Buburuza and enter the six-digit code currently shown for that entry. On the web, choose Verify.
5. Save the recovery codes using Copy or Download and confirm that you have stored them privately.

**Troubleshooting and important distinctions**

- If the code is rejected, check that the authenticator entry is for Buburuza and enter the current code.
- Set up passkey instead or Use a passkey instead returns to the alternative security setup shown in the flow.
- Do not share the setup key, QR code, authenticator code, or recovery codes.

<a id="recover-access" />

## Recover access with a recovery code

_Applies to: Mobile and web_

Use the recovery path when you cannot use your usual sign-in method. Each recovery code works once. The recovery screen and the authenticator-help link are separate options.

1. At sign-in, choose Recover. The web link appears beside Lost access to the passkey?; mobile shows Having issues? Recover.
2. Enter the email for your existing account and complete the email check in the recovery flow.
3. At Enter a recovery code, enter an unused code saved during setup.
4. Read the confirmation that the code has been used and check the remaining-code count shown.
5. Choose Set up passkey to add a working passkey on this device. On the web, Skip for now continues and reminds you to add one later in Settings.

**Troubleshooting and important distinctions**

- If you have lost the recovery codes, use Contact support on that screen.
- If you are on the web authenticator challenge and have lost the authenticator app, its displayed alternative is Contact support. Do not assume an unseen recovery shortcut is present.
- Never include a recovery code or authenticator secret in a support message.

## Review and sign out other sessions

_Applies to: Mobile and web_

Review your active sessions or trusted devices when you no longer use a device or do not recognize a sign-in.

1. Open Settings, then Active sessions.
2. Inspect the device/browser, location, and last-active information. Identify Current session or This device before acting.
3. On mobile, choose Terminate for the unwanted session, check the confirmation, and choose Yes, terminate.
4. On the web, choose the individual session’s sign-out action and confirm Sign out session.
5. To remove other active web sessions together, choose Sign out all other sessions, read the count, and confirm. The dialog says the current session stays signed in.
6. Check the list or completion notice. If you also want to remove a saved sign-in method, use Passkeys separately.

**Troubleshooting and important distinctions**

- Signing out a session does not remove its passkey. A device with an allowed passkey may be able to sign in again.
- If you do not recognize a session, review the stored passkeys and use the official support route for an account-security issue.

<a id="remove-passkey" />

## Remove a saved passkey

_Applies to: Web_

Removing a passkey changes a saved sign-in method. It is separate from signing out an active session.

1. Open Settings, then Passkeys.
2. Identify the passkey by its password manager or device and its added or last-used information.
3. Choose its removal action.
4. Read Remove this passkey? and confirm which sign-in method will stop working.
5. Choose Remove passkey to continue, or Keep it to cancel.
6. Complete any passkey verification shown and check the Passkey removed result. Review Active sessions separately if you also want a current session signed out.

**Troubleshooting and important distinctions**

- Make sure you retain a working way to access the account before removing a sign-in method.
- Signing out a session does not remove its passkey, and removing a passkey should not be assumed to terminate existing sessions.

## Review and end mobile account sessions

_Applies to: Mobile_

Review the devices signed in to your account and end an individual session or the other sessions while preserving your current one.

1. Open Profile, then Privacy & security and Trusted devices. If your app shows Security instead, open Login activity.
2. Review Current session separately from Active session. Compare the device, app/browser, location and date.
3. Select an active session to inspect its Application, Location, IP address and last activity.
4. Choose Terminate this session. Check the selected device in the confirmation, then choose Yes, terminate; use No, keep to cancel.
5. Enter your app passcode when requested. Check Session is terminated and confirm the intended device was removed from the list.
6. To end the other sessions together, choose Terminate all other sessions. Its explanation says the current device stays signed in.
7. Use If inactive for to review the inactivity expiry. If the picker offers 1 week, 1 month, 3 months or 6 months, choose the period you intend to use; choose Cancel to leave it unchanged.

**Troubleshooting and important distinctions**

- Identify Current session before ending other sessions.
- Session sign-out and removal of a saved passkey are separate actions.
- The app-passcode step is authentication for the termination action; it does not create a new passcode.

## Change your mobile login password

_Applies to: Mobile_

The password-based mobile account has a Login password change flow. You verify access before entering and repeating a new password.

1. Open Profile, then Privacy & security and Login password.
2. Enter your app passcode when requested.
3. Enter your old login password.
4. On Create new login password, enter the new password, then repeat it on the next screen.
5. Check Login password changed on Privacy & security. If your Privacy settings name this Master password, use Continue between the current, new and repeat-password steps.

**Troubleshooting and important distinctions**

- This is the account login password, not the app passcode, card PIN or wallet-backup password.
- Never share your current or new password with support.
- If you do not know the old password, use the separate forgotten-login-password flow where offered.

<a id="change-app-pin" />

## Change your six-digit mobile app passcode

_Applies to: Mobile_

Your app passcode protects access to the mobile app and sensitive settings. It is separate from your login password and card PIN.

1. Open Profile, then Privacy & security and App passcode.
2. Enter your old six-digit app passcode.
3. On Create new passcode, enter the new six-digit code.
4. On Repeat new passcode, enter it again.
5. Check App passcode is set! on Privacy & security. If your Privacy settings name this App pin, check for Your pin has been changed.

**Troubleshooting and important distinctions**

- Changing the app passcode does not change your card PIN, login password or wallet-backup password.
- Never share your passcode with support.
- If the old passcode is unknown, the change screen is not a recovery procedure.

<a id="mobile-password-signin" />

## Sign in with email or phone and a login password

_Applies to: Mobile_

The mobile password sign-in screen accepts your email address or mobile number with the login password.

1. Choose Log in from welcome or the signup page.
2. Use the email form, or switch to mobile and select the country calling code.
3. Enter the account email or phone number and the login password. Use the eye control only when you can view the screen privately.
4. Choose Log in.
5. If you have forgotten the login password, choose Forgot password to start the email or mobile recovery route.
6. Use Google or Apple only when that provider option is offered for the account and you intend to sign in through it.

**Troubleshooting and important distinctions**

- The login password is not the six-digit app passcode used to unlock the app.
- Google login is separate from Google Authenticator two-factor authentication.
- Use the sign-in method shown for your account; a passwordless passkey flow has different steps.

<a id="reset-mobile-login-password" />

## Reset a forgotten mobile login password

_Applies to: Mobile_

Forgot password offers email and mobile routes. This resets the login password, not a wallet recovery phrase or card PIN.

1. From the password login screen, choose Forgot password.
2. For email recovery, enter the account email and choose Continue. Check your email says instructions were sent to the masked address; use those instructions to reach the password-reset step.
3. For mobile recovery, choose Use mobile, select the country code and enter the number. Continue and enter the six-digit verification code sent to that number.
4. On Create your new login password, enter and repeat the new password. The shown requirement is at least eight characters. Choose Continue.
5. Return to the matching email or mobile Log In form and use the new login password.

**Troubleshooting and important distinctions**

- Check the masked destination and resend countdown if a message has not arrived.
- Do not confuse a password reset with changing an app passcode or unlocking a wallet backup.
- After resetting the login password, review Login activity and end any sessions you no longer want.

## Set up an authenticator during mobile onboarding

_Applies to: Mobile_

The onboarding 2FA introduction offers Enable 2FA or Skip for now. Setup links an authenticator using its key and verifies a time-based code.

1. Choose Enable 2FA during personal onboarding, or open Profile → Privacy & security → 2FA. In settings, enter your app passcode when requested.
2. Choose the authenticator offered: Google Authenticator or Authy.
3. Copy the setup key into a new entry in the named authenticator. Keep the key private.
4. Choose Next, then enter the current six-digit time-based code for that Buburuza entry.
5. Choose Next and check 2FA is set in the settings route.

**Troubleshooting and important distinctions**

- Use the current code from the matching authenticator entry; a phone SMS code is a different credential.
- Never send the setup key or current code to support.
- If you cannot use the configured authenticator, follow the separate recovery flow actually offered by your account.

<a id="enable-mobile-biometrics" />

## Enable biometric access in the mobile app

_Applies to: Mobile_

Biometrics appears as a security setting with an app-passcode check and a device authentication result.

1. Open Profile, then Privacy & security.
2. Choose Biometrics and enter your app passcode when requested.
3. Complete the biometric prompt shown by your device.
4. Check the Biometrics enabled confirmation and enabled toggle in Privacy & security.

**Troubleshooting and important distinctions**

- Follow the device’s biometric prompt. If the device cannot authenticate you, use the alternative offered on the app’s authentication screen.
- Biometrics does not replace the need to keep your app passcode private.
